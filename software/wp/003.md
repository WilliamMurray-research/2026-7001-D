# Model Selection for Offline Metadata Extraction   
## Technical Assessment Report  
###  
### bonsai‑8B‑1bit vs Gemma 4 E2B

---

## 1. Executive Summary

Gemma 4 E2B is the preferred primary model for directory‑level metadata extraction. It provides stronger instruction following, lower hallucination rates, more stable JSON output, and a significantly larger context window. These properties directly improve the reliability of metadata ingestion into PostgreSQL and relationship construction in Memgraph.

bonsai‑8B‑1bit remains valuable as an edge‑deployment profile. Its extremely small footprint and high throughput make it suitable for lightweight or distributed environments, but its aggressive quantization introduces occasional schema drift that requires additional guard‑rails.

---

## 2. Evaluation Criteria

The Directory‑Level Governance System requires an offline model capable of:

- **Structured extraction** from README and TOML  
- **Deterministic JSON** suitable for ingestion  
- **Low hallucination** to preserve metadata integrity  
- **Long‑context processing** for multi‑file directories  
- **Stable low‑temperature behavior**  
- **Offline inference** with no external dependencies  

These criteria reflect the system’s need for predictable, governed metadata extraction.

---

## 3. Model Characteristics

### 3.1 bonsai‑8B‑1bit

- **Model size:** approximately 1.1–1.2 GB  
- **Quantization:** 1‑bit, highly compressed  
- **Performance:** high throughput on low‑resource devices  
- **Context window:** limited compared to modern small models  
- **Strengths:**  
  - extremely lightweight  
  - fast inference  
  - suitable for distributed or constrained environments  
- **Weaknesses:**  
  - occasional schema drift in structured JSON  
  - reduced precision due to aggressive quantization  
  - limited ability to ingest large directory structures

### 3.2 Gemma 4 E2B

- **Model size:** approximately 7.2 GB  
- **Quantization:** efficient but not extreme  
- **Performance:** strong throughput on consumer hardware  
- **Context window:** 128K tokens  
- **Strengths:**  
  - excellent instruction following  
  - stable structured JSON output  
  - low hallucination rates  
  - robust long‑context reasoning  
- **Weaknesses:**  
  - larger footprint  
  - requires more memory than bonsai‑8B‑1bit

---

## 4. Comparative Analysis

### 4.1 Instruction Following

Gemma 4 E2B consistently adheres to strict extraction schemas, even under low temperature. This is essential for predictable metadata ingestion. bonsai‑8B‑1bit performs well but exhibits occasional deviations when handling nested structures or multiple TOML files.

### 4.2 Deterministic JSON Output

Gemma 4 E2B produces stable JSON across repeated runs. bonsai‑8B‑1bit may require additional validation layers to ensure schema compliance.

### 4.3 Hallucination Behavior

Gemma 4 E2B demonstrates lower hallucination rates, reducing the risk of phantom tags, dependencies, or provenance fields. bonsai‑8B‑1bit is generally reliable but more susceptible to minor drift due to quantization.

### 4.4 Context Window

Gemma’s 128K context window allows ingestion of entire directory structures, including README files, multiple TOML sidecars, and system prompts. bonsai‑8B‑1bit’s smaller window limits batch extraction and may require multiple passes.

### 4.5 Hardware Footprint

bonsai‑8B‑1bit excels in environments with limited memory or CPU resources. Gemma 4 E2B requires more memory but remains practical on modern laptops and desktops.

---

## 5. Implications for the Governance System

### PostgreSQL Metadata Layer

Gemma 4 E2B’s deterministic JSON reduces the need for defensive parsing logic. bonsai‑8B‑1bit may require additional validation to prevent malformed entries.

### Memgraph Relationship Layer

Gemma’s stronger reasoning improves dependency extraction and relationship mapping. bonsai‑8B‑1bit performs adequately but may miss subtle relationships in complex directories.

### Bash Sync Engine

Gemma simplifies the sync engine by reducing the need for retries or schema correction. bonsai‑8B‑1bit benefits from guard‑rails such as JSON schema validation and fallback prompts.

---

## 6. Recommendation

### Primary Model

Gemma 4 E2B should be the default metadata‑extraction model. It provides the most reliable structured output, the best long‑context performance, and the lowest risk of metadata drift.

### Secondary / Edge Profile

bonsai‑8B‑1bit should be retained as the lightweight profile for environments where memory, storage, or CPU constraints are significant. It remains a strong option for distributed or mobile deployments.

---

## 7. Conclusion

For the Directory‑Level Governance System, Gemma 4 E2B offers superior reliability, determinism, and context handling. bonsai‑8B‑1bit remains valuable for constrained environments but requires additional safeguards. Together, they form a complementary pair: Gemma for canonical extraction, bonsai for edge deployment.
