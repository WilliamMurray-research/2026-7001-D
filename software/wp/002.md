# Configuring Sourcetree and Obsidian with Git on Ubuntu Linux  

## **1. Introduction**

This whitepaper describes a complete, reproducible workflow for integrating Obsidian (a Markdown‑based knowledge management system) with Git and Sourcetree on Ubuntu Linux. The goal is to provide a robust environment for versioning personal knowledge bases, technical notes, research logs, and documentation using a graphical Git client.

The document covers installation, configuration, repository management, workflow design, and operational considerations.

---

# **2. System Overview**

### **2.1 Components**

- **Obsidian**: A local Markdown editor and knowledge graph tool.
- **Git**: Distributed version control system.
- **Sourcetree**: A graphical Git client originally built for Windows/macOS, run on Ubuntu via Wine.
- **Ubuntu Linux**: Host operating system.
- **Optional remote services**: GitHub, GitLab, Gitea, or any SSH‑accessible Git server.

### **2.2 Architectural Model**

The architecture is simple:

1. Obsidian stores all notes as plain text Markdown files.
2. Git tracks changes within the vault directory.
3. Sourcetree provides a visual interface for commits, branches, diffs, and remote synchronization.
4. Optional remotes provide off‑device backup and collaboration.

This model ensures transparency, auditability, and long‑term durability of knowledge assets.

# **3. Installation Procedures**

## **3.1 Install Git**

Git is available in Ubuntu’s repositories.

```
sudo apt update
sudo apt install git
```

Configure global identity:

```
git config --global user.name "Your Name"
git config --global user.email "your_email@example.com"
```

## **3.2 Install Obsidian**

Download the latest `.deb` package and install:

```
wget https://github.com/obsidianmd/obsidian-releases/releases/latest/download/obsidian_amd64.deb
sudo apt install ./obsidian_amd64.deb
```

Create a vault, for example:

```
~/Documents/obsidian-vault/
```

## **3.3 Install Wine**

Sourcetree requires Wine because it is not natively available for Linux.

```
sudo dpkg --add-architecture i386
sudo apt update
sudo apt install wine64 wine32
```

Verify:

```
wine --version
```

## **3.4 Install Sourcetree**

Download the Windows installer:

```
wget https://downloads.atlassian.com/software/sourcetree/windows/SourcetreeSetup.exe
```

Run the installer:

```
wine SourcetreeSetup.exe
```

Sourcetree installs under:

```
~/.wine/drive_c/Program Files/Atlassian/Sourcetree/
```

Launch Sourcetree:

```
wine ~/.wine/drive_c/Program\ Files/Atlassian/Sourcetree/Sourcetree.exe
```

# **4. Repository Configuration**

## **4.1 Initialize Git in the Obsidian Vault**

Navigate to the vault:

```
cd ~/Documents/obsidian-vault/
git init
```

## **4.2 Create a .gitignore**

Obsidian generates metadata and cache files that should not be versioned.

Example `.gitignore`:

```
.obsidian/cache/
.obsidian/workspace
.obsidian/plugins/obsidian-sync/
.obsidian/plugins/obsidian-daily-notes/
.DS_Store
Thumbs.db
```

This keeps the repository clean and focused on content.

## **4.3 Add a Remote Repository (Optional)**

Example using SSH:

```
git remote add origin git@github.com:username/obsidian-vault.git
```

Test connectivity:

```
ssh -T git@github.com
```

# **5. Integrating Sourcetree with the Vault**

## **5.1 Add the Repository**

In Sourcetree:

1. Select “Add Existing Repository”.
2. Choose the vault directory.
3. Sourcetree loads the repository and displays:
   - Commit history
   - Branches
   - Staged/unstaged changes
   - Diff viewer

## **5.2 Commit Workflow**

Typical workflow:

1. Edit notes in Obsidian.
2. Open Sourcetree.
3. Stage modified files.
4. Write a commit message.
5. Commit changes.
6. Push to remote (optional).

This mirrors the GitHub Desktop workflow but with more advanced features.

# **6. Optional Enhancements**

## **6.1 Obsidian Git Plugin**

The Obsidian Git plugin can automate commits or provide quick in‑editor Git actions. It is optional because Sourcetree already provides full Git functionality.

## **6.2 SSH Key Management**

Generate a key:

```
ssh-keygen -t ed25519 -C "your_email@example.com"
```

Start the agent:

```
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
```

Add the public key to your Git hosting provider.

## **6.3 Backup Strategy**

Recommended approach:

- Local Git repository for versioning.
- Remote Git server for off‑device backup.
- Optional encrypted backup using tools like restic or borg.

---

# **7. Operational Considerations**

## **7.1 Merge Conflicts**

Markdown files are simple text, so conflicts are easy to resolve. Sourcetree provides a visual diff tool that simplifies conflict resolution.

## **7.2 File Locking**

Obsidian does not lock files. Git operations are safe as long as commits are made when Obsidian is not actively writing metadata.

## **7.3 Performance**

Large vaults (10k+ notes) remain performant because Git handles text efficiently. Sourcetree may require additional Wine configuration for optimal performance.

## **7.4 Security**

Key considerations:

- Use SSH rather than HTTPS for authentication.
- Avoid storing secrets inside the vault.
- Ensure remote repositories are private if notes contain sensitive information.

---

# **8. Recommended Workflow Model**

1. Write and organize notes in Obsidian.
2. Use Git to track changes.
3. Use Sourcetree for:
   - Visual commit graph
   - Branch management
   - Diff inspection
   - Remote synchronization
4. Use remotes for backup and collaboration.
5. Use `.gitignore` to keep the repository clean.

This model provides a stable, transparent, and maintainable knowledge management system.

---

# **9. Conclusion**

Sourcetree and Obsidian can be integrated seamlessly on Ubuntu using Git and Wine. The resulting workflow offers a powerful combination of visual version control, Markdown‑based knowledge management, and distributed backup. This approach is suitable for engineers, researchers, and developers who require a durable, auditable, and flexible system for managing technical notes and documentation.
