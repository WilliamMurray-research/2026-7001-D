# Technical Specification: Local Git Integration and Optional Obsidian Workflow for AI‑Driven Engineering

1. Purpose
This document defines the architecture, workflows, and operational patterns required to integrate local Git repositories with a fully local AI engineering stack. It also describes an optional integration with Obsidian, enabling a unified environment for:

- version‑controlled code  
- version‑controlled documentation  
- agentic operations across repositories  
- project‑wide reasoning  
- RAG‑powered knowledge retrieval  
- local‑only privacy  

The goal is to create a local AI engineer capable of interacting with Git repositories, generating documentation, and maintaining project knowledge inside Obsidian.

3. Git Integration Architecture

3.1 High‑Level Flow
1. User triggers a Git‑related task.  
2. Anything LLM routes the task to OpenCode.  
3. OpenCode loads the project session.  
4. OpenCode calls Git tools.  
5. Tools execute Git commands locally.  
6. OpenCode applies reasoning and generates patches.  
7. Git commits changes.  
8. Optional: Obsidian updates documentation automatically.

---

3.2 Required Git Tools
OpenCode must be configured with Git‑aware tools.

Tool: git_status()
Returns:

- modified files  
- untracked files  
- staged changes  

Tool: git_diff(path)
Returns:

- diff for a specific file  
- unified diff format  

Tool: gitapplypatch(diff)
Applies:

- AI‑generated patches  
- structured diffs  

Tool: git_commit(message)
Creates:

- atomic commits  
- structured commit messages  

Tool: git_checkout(branch)
Switches branches.

Tool: gitcreatebranch(name)
Creates new branches.

Tool: git_log()
Returns commit history.

4. Agent Workflow Specification for Git Operations

4.1 Workflow Trigger
Triggered by:

- Anything LLM workflow  
- OpenCode project session  
- Codium IDE command  
- CLI invocation  

---

4.2 Workflow Steps

Step 1 — Initialize Git Context
OpenCode loads the repository root.

Step 2 — Inspect Repository
OpenCode calls:

- git_status()  
- git_log()  
- scan_directory()  

Step 3 — Reasoning Loop
OpenCode determines:

- required changes  
- patch structure  
- commit strategy  
- branch strategy  

Step 4 — Patch Generation
OpenCode generates:

- diffs  
- file rewrites  
- documentation updates  

Step 5 — Apply Changes
OpenCode calls:

- write_file()  
- gitapplypatch()  

Step 6 — Commit
OpenCode calls:

- git_commit(message)  

Step 7 — Optional Branching
OpenCode may:

- create feature branches  
- merge branches  
- rebase  

Step 8 — Reporting
OpenCode returns:

- summary of changes  
- commit details  
- next‑step suggestions
