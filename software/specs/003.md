# Technical Specification: Sandboxed Development Environments on Ubuntu (venv, system sandboxing, Docker)

1. Purpose
This document defines a complete, layered approach to sandboxing development environments on Ubuntu.  
It covers:

- Python virtual environments (venv)  
- OS‑level sandboxing tools  
- User‑level isolation  
- Docker containerization  
- Integration with local AI engineering workflows  

The goal is to provide a secure, reproducible, isolated environment for development, experimentation, and agentic automation.

---

2. System Overview

2.1 Layered Isolation Model
Sandboxing is implemented in three layers:

1. Application‑level isolation  
   Python venv, pip constraints, local dependencies.

2. System‑level isolation  
   AppArmor, systemd sandboxing, restricted users, chroot.

3. Container‑level isolation  
   Docker, Podman, OCI containers.

Each layer can be used independently or combined for maximum security.

---

3. Python Virtual Environments (venv)

3.1 Purpose
Python venv provides:

- isolated Python interpreter  
- isolated dependencies  
- reproducible environments  
- safe execution for AI agents  

Explore more:  
Python venv basics

---

3.2 Creating a venv
`
python3 -m venv .venv
`

3.3 Activating the venv
`
source .venv/bin/activate
`

3.4 Installing dependencies
`
pip install -r requirements.txt
`

3.5 Freezing dependencies
`
pip freeze > requirements.txt
`

3.6 Best Practices
- One venv per project  
- Store venv outside Git  
- Use requirements.txt or pyproject.toml  
- Use venv for AI agent tool execution

4. System‑Level Sandboxing on Ubuntu

4.1 Purpose
System‑level sandboxing restricts:

- filesystem access  
- network access  
- process capabilities  
- user permissions  

It protects the host from misbehaving tools or agentic automation.

---

4.2 Restricted User Accounts
Create a non‑privileged user:

`
sudo adduser sandbox
sudo usermod -s /usr/sbin/nologin sandbox
`

Use this user for:

- AI agent tool execution  
- file operations  
- testing untrusted scripts  

Explore more:  
restricted users

---

4.3 AppArmor Profiles
AppArmor provides mandatory access control.

Enable AppArmor
`
sudo apt install apparmor apparmor-utils
`

Create a profile
`
sudo aa-genprof /usr/bin/python3
`

Apply restrictions
- read‑only directories  
- no network  
- limited execution  

Explore more:  
AppArmor basics

---

4.4 systemd Sandboxing
Systemd units can sandbox processes.

Example service:

`
[Service]
ExecStart=/usr/bin/python3 script.py
ProtectSystem=full
ProtectHome=yes
PrivateTmp=yes
NoNewPrivileges=yes
`

Provides:

- read‑only system  
- isolated /tmp  
- no privilege escalation  

Explore more:  
systemd sandboxing

---

4.5 chroot Environments
Chroot creates a minimal filesystem jail.

Create a chroot directory
`
sudo mkdir -p /srv/chroot/env
sudo debootstrap stable /srv/chroot/env
`

Enter the chroot
`
sudo chroot /srv/chroot/env
`

Use chroot for:

- testing  
- isolated builds  
- agentic execution  

Explore more:  
chroot basics

5. Docker Containerization

5.1 Purpose
Docker provides full container isolation:

- filesystem isolation  
- network isolation  
- resource limits  
- reproducible environments  
- safe execution for AI agents  

Explore more:  
Docker basics

---

5.2 Install Docker
`
sudo apt install docker.io
sudo systemctl enable --now docker
`

---

5.3 Create a Dockerfile
Example Python sandbox:

`
FROM ubuntu:22.04

RUN apt update && apt install -y python3 python3-venv

WORKDIR /app
COPY . .

RUN python3 -m venv /app/.venv
RUN /app/.venv/bin/pip install -r requirements.txt

CMD ["/app/.venv/bin/python", "main.py"]
`

---

5.4 Build the container
`
docker build -t sandbox-app .
`

5.5 Run the container
`
docker run --rm -it sandbox-app
`

---

5.6 Docker Sandbox Features
- read‑only filesystem  
- no network  
- limited memory  
- limited CPU  
- no privileged mode  

Example:

`
docker run --rm -it \
  --read-only \
  --network=none \
  --memory=512m \
  --cpus=1 \
  sandbox-app
`

7. Best Practices

7.1 Use venv for Python isolation
- one venv per project  
- freeze dependencies  
- avoid system Python  

7.2 Use restricted users for agent execution
- no login shell  
- minimal permissions  

7.3 Use AppArmor for high‑risk tools
- restrict filesystem  
- restrict network  

7.4 Use Docker for full isolation
- read‑only filesystem  
- no network  
- resource limits  

7.5 Combine layers
Example:

- Docker container  
- running as restricted user  
- with AppArmor profile  
- executing Python inside venv  

This is maximum isolation.
