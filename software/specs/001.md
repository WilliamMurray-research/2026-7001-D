
# Technical Specification. 
## Agentic Directory Operations in a Local AI Engineering Stack

1. Purpose
This document defines the architecture, tooling, and workflow required to enable agentic, recursive directory‑level operations within a fully local AI engineering environment.  
The goal is to allow AI agents to:

- read, analyze, and transform files  
- traverse directories and subdirectories  
- execute tools and scripts  
- perform multi‑step reasoning over a codebase  
- integrate with IDE workflows  
- operate entirely offline  

This capability turns the stack into a local AI engineer capable of acting on entire projects.

3. Directory‑Level Agent Architecture

3.1 High‑Level Flow
1. User triggers a workflow (IDE, CLI, or Anything LLM).  
2. Anything LLM routes the task to OpenCode.  
3. OpenCode loads the project session.  
4. OpenCode calls filesystem tools.  
5. Tools recursively traverse directories.  
6. OpenCode applies reasoning and transformations.  
7. Tools write results back to disk.  
8. Optional: RAG retrieves context from ingested project files.

---

3.2 Required Tools
OpenCode must be configured with a set of filesystem tools.  
Each tool is a callable function.

Tool: scan_directory(path)
- Recursively walks directories  
- Returns file list with metadata  
- Filters by extension or pattern  

Tool: read_file(path)
- Reads file contents  
- Returns text for analysis  

Tool: write_file(path, content)
- Writes modified content back to disk  
- Supports atomic writes  

Tool: run_script(command)
- Executes shell or Python scripts  
- Used for linting, formatting, testing  

Tool: apply_patch(path, diff)
- Applies structured diffs  
- Ensures safe code modifications

4. Agent Workflow Specification

4.1 Workflow Trigger
Workflows may be triggered by:

- Anything LLM workflow  
- OpenCode project session  
- Codium IDE command  
- CLI invocation  

---

4.2 Workflow Steps

Step 1 — Initialize Project Session
OpenCode loads a persistent session tied to the project root.

Step 2 — Directory Scan
OpenCode calls scandirectory(rootpath) to obtain:

- file list  
- directory structure  
- file types  
- sizes  
- timestamps  

Step 3 — File Classification
OpenCode classifies files into:

- source code  
- configuration  
- documentation  
- assets  
- tests  

Step 4 — Reasoning Loop
OpenCode performs multi‑step reasoning:

- identify required transformations  
- plan execution steps  
- determine dependencies  
- generate patches or scripts  

Step 5 — File Operations
OpenCode calls:

- read_file()  
- write_file()  
- apply_patch()  

Step 6 — Optional Script Execution
OpenCode may call:

- linters  
- formatters  
- test runners  
- build tools  

Step 7 — Validation
OpenCode verifies:

- syntax correctness  
- dependency integrity  
- test pass/fail  

Step 8 — Reporting
OpenCode returns structured output:

- summary of changes  
- list of modified files  
- reasoning trace  
- next‑step suggestions

6. Security Model

6.1 Local‑Only Execution
All operations occur locally:

- no cloud inference  
- no external API calls  
- no remote storage  

6.2 Restricted Tooling
Tools must be sandboxed:

- no arbitrary network access  
- no destructive commands unless explicitly allowed  

6.3 Audit Logging
OpenCode should log:

- tool calls  
- file modifications  
- reasoning steps
